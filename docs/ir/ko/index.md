# IRes

[English](../en/index.md)

IRes는 [ESMeta][esmeta]가 ECMAScript 명세를 컴파일해서 얻는 중간 언어다. 이 언어를
여기에 직접 적어 두면 명세를 그대로 실행할 수 있다. 인터프리터를 따로 손으로
만들어 붙이지 않아도 된다.

프로그램은 함수들의 표다. 그중 하나가 main 함수다. 프로그램을 실행한다는 것은 이
함수 위에 문맥을 하나 열고, 더 남은 것이 없을 때까지 본문을 한 단계씩 진행하는
것이다.

<a id="program"></a>
<a id="func"></a>
```spectec
syntax program = (func)*

syntax func = 
   | {bool funcKind id (param)* type inst}
```

## 규칙 읽는 법

이 명세의 본문은 대부분 *추론 규칙(inference rule)*이다. 규칙 하나는 전제 여럿과
결론 하나로 이루어진다. 전제가 모두 성립하면 결론도 성립한다는 뜻이고, 그렇게
규칙을 이어 붙인 것을 도출(derivation)이라고 한다.

어떤 경우를 두고 결론을 낼 규칙이 하나도 없으면 도출도 없다. 그러면 그 프로그램은
답을 얻지 못하고 [멈춰 선다](running.md#stopping). 규칙이 없다는 것이 곧 답이 없다는
뜻이라는 점은 이 명세 전체에서 되풀이된다.

규칙은 관계마다 여러 개씩 붙는다. 명령을 한 단계 진행시키는 규칙들이 있고, 식을
값으로 옮기는 규칙들이 있다. 아래에서 그냥 "규칙"이라고 하면 모두 이 추론 규칙을
가리킨다.

## 표기법

산문에는 나오지만 IRes 자체에는 없는 표시가 둘 있다.

<a id="option_get"></a>
**!** 는 단언이고, ECMA-262에서 쓰는 것과 같다. `Let x be ! f(y)`는 `f(y)`의 결과가
선택적이라는 것, 그 결과가 있다고 단언한다는 것, 그리고 `x`를 그 안의 값에
묶는다는 뜻이다. 결과가 없는 도출은 아예 없다. 그래서 그런 곳에 다다른 프로그램은
답을 얻지 못하고 [멈춰 선다](running.md#stopping).

<a id="check_let"></a>
**Let!<sub>type</sub>** 는 모양을 먼저 확인하고 묶는 표시다. `Let!type x be y`는
`y`가 규칙이 기대하는 타입이나 패턴에 맞는지 보고, 맞을 때만 `x`를 묶는다는
뜻이다. **!** 와 마찬가지로 확인에 실패하면 도출이 없다.

둘 다 인터프리터가 실제로 밟는 단계는 아니다. 규칙이 기대는 조건을 적어 둔
것뿐이다.

## 평가 방식이 둘인 이유

식은 **big-step**으로 평가한다. 관계 하나가 식을 값까지 한 번에 옮기고, 부분식은
같은 관계의 전제로 처리한다. 명령은 **small-step**으로 평가한다. 관계 하나가
상태와 남은 명령들을 받아서 다음 상태와 다음 명령 열을 내놓는다.

둘이 표현해야 하는 것이 다르기 때문이다. 식에는 도중에 멈춰 둘 제어 흐름이 없다.
그래서 big-step으로 써도 잃는 것이 없고 읽기도 쉽다. 명령 열은 다르다. 호출은
호출자를 잠시 밀어 두었다가 나중에 다시 이어야 한다. 그러려면 남은 명령들이 도출
안에 숨어 있으면 안 되고 구성에 드러나 있어야 한다.

이 선택 때문에 눈에 띄는 결과가 하나 생기는데, 명세의 나머지는 그것을 전제로
쓰여 있다. 식을 big-step으로 평가하면 값 대신 트랩을 내보낼 길이 없다. 그래서
식에서 생긴 실패는 트랩이 되지 못하고 그냥 *멈춰 선다*. 이름이 붙는 실패는 명령
쪽 실패뿐이다. [프로그램이 멈추는 방식](running.md#stopping)을 함께 보라.
